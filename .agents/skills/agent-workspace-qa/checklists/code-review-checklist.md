# 代码审查清单

## 架构与设计

- [ ] 代码组织符合项目结构
- [ ] 没有引入不必要的依赖
- [ ] 新增模块遵循了现有的设计模式
- [ ] 接口设计合理（参数、返回值、异常）

## 功能正确性

- [ ] 实现了需求文档中的所有功能点
- [ ] 边界情况已处理（空值、非法输入、上限、下限）
- [ ] 异常场景已考虑（网络超时、服务不可用、数据不存在）
- [ ] 并发安全性已考虑（竞态条件、死锁）

## 安全性

- [ ] 用户输入已校验（XSS、SQL注入、路径遍历）
- [ ] 敏感信息未硬编码（密码、密钥、Token）
- [ ] 权限检查已实现
- [ ] 日志未泄露敏感信息

## 可维护性

- [ ] 代码有适当的注释（非显而易见的逻辑）
- [ ] 函数/方法职责单一
- [ ] 变量/函数命名清晰
- [ ] 没有重复代码
- [ ] 没有过深的嵌套

## 代码质量

- [ ] 没有 TODO/FIXME 遗留
- [ ] 没有注释掉的代码
- [ ] 没有调试代码（console.log、debugger）
- [ ] Lint 通过
- [ ] 类型定义完整（TypeScript 或其他类型系统）

## 测试

- [ ] 新增代码有对应的测试
- [ ] 测试覆盖了正常路径和异常路径
- [ ] 测试命名清晰，容易理解测试意图
- [ ] 测试没有依赖外部环境（网络、数据库）
