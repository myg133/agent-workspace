# 测试用例生成流程

## 触发时机

BA Agent 创建需求后，QA Agent 接收到需求文档时。

## 流程

### Step 1: 读取需求文档

```
1. 读取 BA/demands/REQ-xxx/demand.md
2. 读取 BA/demands/REQ-xxx/acceptance.md
3. 理解需求的功能要点和验收标准
```

### Step 2: 分解测试场景

```
对每个验收标准，分解测试场景：

AC-01: 邮箱格式校验
├── TC-001: 输入有效邮箱 → 通过
├── TC-002: 输入无@符号的邮箱 → 拒绝
├── TC-003: 输入空邮箱 → 拒绝
├── TC-004: 输入超长邮箱 → 拒绝
└── TC-005: 输入带特殊字符的邮箱 → 根据规则判断

AC-02: 密码错误提示
├── TC-006: 输入错误密码 → 显示错误提示
├── TC-007: 连续输入错误密码 → 触发锁定机制
└── TC-008: 密码为空 → 提示必填
```

### Step 3: 编写测试用例

```
在 BA/demands/REQ-xxx/test-cases/ 下创建测试用例文件

每个用例包含：
- 用例编号
- 关联的验收标准
- 前置条件
- 测试步骤
- 预期结果
- 优先级
```

### Step 4: 分类标记

```
标记测试用例的类型：
- [功能] 功能测试
- [边界] 边界测试
- [异常] 异常测试
- [性能] 性能测试
- [安全] 安全测试
```

### Step 5: 通知 Dev Agent

```
1. 测试用例编写完成
2. 通知 Dev Agent 测试用例已就绪
3. Dev Agent 在开发时需确保测试覆盖这些用例
```
