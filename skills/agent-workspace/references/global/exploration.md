# 探索权唯一：BA、Explore、Dev 怎么分

> 问题：BA 先探索一遍，子 Agent 又探索一遍。
> 根因通常不是模型笨，而是：BA 越界做了代码探索，或者探索结果没有变成子 Agent 可用的证据。

## 1. 一条规则

**每个任务只有一个“代码探索 owner”。**

| 角色 | 探索范围 | 不做什么 |
|------|----------|----------|
| BA | 业务、需求、验收、文档、接口、依赖 | 深读实现、画完整调用链 |
| Explore | 代码路径、调用链、风险 | 写需求、改代码 |
| Dev | 任务相关文件、实现细节 | 全仓库重扫 |
| QA | diff、AC、关键风险 | 重新探索整个架构 |

一个任务里，**BA 和子 Agent 不能同时深挖同一批代码**。

## 2. 两层探索

| 层 | owner | 产出 |
|----|-------|------|
| 业务探索 | BA | 需求、AC、边界、依赖、风险 |
| 代码探索 | Explore / Dev | path:line 证据、调用链、实现方案 |

BA 为了写验收可以读接口、契约、测试名，但不要读到实现细节。
需要实现级理解时，派 Explore/Dev，让它们成为唯一 owner。

## 3. Fresh 子 Agent 契约

子 Agent 默认**零上下文**：

- briefing 里没写的，它就等于不知道；
- 它不会自动继承 BA 的对话；
- 角色 prompt 里的“先读项目”会让它重扫全仓库。

所以任务卡必须写清：

~~~text
父会话已完成部分探索。
先读任务卡里的 evidence。
只验证“待验证项”和本次 diff 相关文件。
不要重扫全仓库；需要扩展时先说明理由。
如果与 evidence 冲突，先指出冲突，再决定是否扩大读取。
~~~

## 4. Evidence 包

这是**每个任务一份的交接证据**，不是项目级 base，不是一堆 md 文档。

最小字段：

| 字段 | 内容 |
|------|------|
| `base_sha` | 探索时的 commit |
| `explored_by` | 谁探索的 |
| `confirmed` | 已确认结论 + path:line |
| `commands` | 跑过的命令和结果 |
| `assumptions` | 假设 |
| `unknowns` | 未确认 / 子 Agent 必须验证 |
| `files_read` | 已读文件，避免重读 |
| `do_not_reread` | 明确不要重读的文件 / 目录 |

模板见 `assets/templates/exploration-evidence.md.tpl`。

## 5. 谁写 evidence

- BA 做了 scope-level 探索 → BA 写；
- Explore 做代码探索 → Explore 写，BA 转交；
- Dev 中途发现新事实 → 更新 evidence，交 QA / 下一个 Dev；
- QA 只补充验证结果，不重写探索结论。

原则：**谁探索，谁留证据；下一个人消费证据，不重新发现。**

## 6. 什么时候允许第二次探索

允许：

- 独立验证高风险结论（安全、资损、权限、并发）；
- 代码在探索后变了，需要看 diff；
- evidence 明显不足；
- 任务跨模块，需要新的调用链。

不允许：

- “我想自己确认一下”但没有新风险；
- 重读 evidence 里已经列出的同一批文件；
- 子 Agent 不看任务卡，直接全仓库扫；
- QA 重新探索架构而不看 diff/AC。

## 7. 和 fork 的关系

- 有 fork：子会话继承父上下文，但仍要明确“不要重新探索项目结构”；
- 没有 fork：evidence 包是必须的，否则 fresh 子 Agent 只能重来；
- fork 不替代身份、claim、worktree 隔离。

## 8. 度量

| 指标 | 健康信号 |
|------|----------|
| 首次编辑前工具调用数 | 低；高说明重复探索 |
| 父子重复读文件比例 | 低；同一文件被完整读两遍就是浪费 |
| 每个任务探索轮数 | BA 少，Explore/Dev 集中 |
| 每个任务 token | 不随“重新熟悉项目”线性增长 |
| 返工率 | 不因减少重复探索而上升 |

## 9. 反模式

- BA 深读实现，子 Agent 再做一遍；
- 任务卡只写“去实现”，不写已确认/待验证/不要重读；
- 子 Agent 收到“先探索项目”但没有 evidence；
- QA 重新画架构图，而不是验证 diff 和 AC；
- 把全量工具日志当 evidence，子 Agent 还是得自己读；
- 为了“独立”让两个 Agent 重复做同一层探索。

## 10. 任务卡字段

~~~text
探索 owner：
已确认（path:line）：
跑过的命令：
假设：
待验证：
已读文件：
不要重读：
~~~
