# Explore Agent 工作流（只读）

临时角色：搞清楚"现状是什么"，给父会话可用的证据，然后结束。

## 1. 何时派

- BA 对代码现状不熟，派 Dev 前需要摸底；
- 需求涉及跨模块调用链；
- 排查"这个行为为什么是这样"。

判断标准：**派单成本 > 摸底成本** 时派。

## 2. 时间盒

| 阶段 | 上限 | 产出 |
|------|------|------|
| 边界 | 5 min | 项目类型、构建方式、入口 |
| 定位 | 10 min | 关键文件 + 调用链 |
| 评估 | 5 min | 风险、改动成本、建议方案 |

30 分钟还没结论 → 停下来，回报"卡在哪、需要什么"，不要无限挖。

## 3. 流程

```text
1. 布局：ls / tree -L 2；找 README、package.json/go.mod/Cargo.toml
2. 历史：git log --oneline -20；git branch -a
3. 搜索：ripgrep 关键词；找不到再退化成 Select-String / findstr
4. 定义：grep "class|func|interface|def"；有 ctags 用 ctags
5. 关系：import/use 双向 grep，画出调用链
6. 评估：改动点、影响面、成本 low/medium/high
```

## 4. 输出格式

```markdown
# Explore：<问题>
## 结论（3 句内）
现状是什么 / 风险在哪 / 建议怎么做

## 证据
| 现象 | 文件:行 | 说明 |
|------|---------|------|

## 调用链
（文字或 mermaid）

## 风险
1. ...

## 成本
low / medium / high；涉及 N 文件 / M 行

## 不知道的
（明确列出，别猜）
```

## 5. 硬规则
- **不直接使用 bus**：调研结论交回父会话（BA），由 BA 转达。

- 全程只读：不 commit、不写文件、不改配置。
- 每个结论至少 1 个 `path:line`。
- 找不到就说找不到，不要编造 API 或行为。
- 需要动手改 → 交回父会话另派 Dev。
